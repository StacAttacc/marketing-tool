# Audit Findings

- `Critical` `.env` git-trackable and already tracked; `.gitignore` disables env ignores, repo contains tracked `.env`; likely secret exposure risk.
- `High` no object-level auth / no tenant boundary; auth only checks "logged in"; budget/campaign/spend/result rows not owned by user; any authenticated user can read/update/delete shared records by id.
- `High` update endpoints bypass create-time invariants; `spend.update`, `result.update`, `campaign.update`, `channel_budget.update` allow invalid date ranges / reassignment / broken business state.
- `High` unauthenticated dev endpoints exist; `/api/dev/seed` can wipe/reseed data, `/api/dev/accoudSeed` can create admin; only blocked when `NODE_ENV === 'production'`.
- `High` hardcoded weak admin creds in source; `admin@admin.com` / `password123`; catastrophic if seed route reachable anywhere non-prod or misconfigured prod.
- `Medium` `deleteBudget` uses stale schema fields; still references `channelBudgetId` on `spend`/`result` after migration to `campaignId`; delete path likely broken / partial / integrity risk.
- `Medium` secondary DB aggregate exposed to all logged-in users; `usersPerChannel` returns global `quizAnswers` counts without scoping; cross-dataset leakage risk.
- `Medium` sensitive data dehydrated into SSR payload; Vue Query state for authenticated pages serialized into `nuxt.payload`; easier data exposure on shared machines / cached HTML / proxies.
- `Medium` error detail leakage possible; `budget/update` can return raw `error.message` to client on internal failures.
- `Medium` full RPC errors logged unsanitized; `console.error(error)` may dump request-derived data / stack / internals into logs.
- `Medium` no visible rate limiting / abuse controls; auth and RPC endpoints exposed to brute force / stuffing / noisy DoS unless external infra handles it.
- `Medium` auth config minimal; email+password only, no visible MFA / verification / allowlist restrictions; weaker for internal-tool exposure.
- `Medium` result filtered list allows larger payloads than peers; `limit` up to `1000`; easier DB/load abuse.
- `Low` route protection opt-in, not global; current pages use `middleware: 'auth'`, but one future page missing it becomes public.
- `Low` frontend auth gate trusts client session state for routing; server still enforces API auth, but route UX can briefly mis-state access during hydration.
- `Low` destructive UI actions have no confirmation step; easier accidental deletes.
- `Low` Nuxt devtools enabled in config; usually dev-only, but still unnecessary surface if shipped incorrectly.
- `Low` no explicit security headers in app config; CSP/HSTS/frame protections not visible in repo; maybe handled upstream, not evident here.
- `Low` `app/env.ts` parses secrets in app layer; currently unused, but future client import could accidentally bundle server secrets.
- `Low` README/schema docs stale vs code; docs still mention `channel_budget_id` for spend/result; raises maintenance and operator error risk.
- `Low` no tests, CI only lint; weak safety net for authz, data integrity, security regressions.
